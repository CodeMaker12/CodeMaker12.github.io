Informatik

Hier beschreibe ich wie man Konzepte in Unity umsetzt.

Falls möglich werden die Unityprojekte als .zip-Datei zum Herunterladen bereitgestellt, sodass jeder die Zusammenhänge selber nachvollziehen kann.

Multiplayer

1. Vorbereitung des Projekts

Um dieser Aleitung folgen zu können muss man einen Unity Account besitzen. Man sollte die Anwendung Unity-Hub und eine Unity-Version heruntergeladen haben.
Diese Anleitung wurde auf Grundlage der 'Unity-Version 6000.3.2f1' geschrieben. Bei älteren und besonders bei neueren Unity-Version sollte es jedoch ebenfalls funktionieren.

1.1 Erstellen eines neuen Unity Projekts (2D)

Starte die Anwendung Unity-Hub.
Der Reiter 'Projekts' wird ausgewählt. Rechts oben wird auf 'New Project' geklickt. Unity stellt unterschiedliche Templates (Vorlagen) zur Verfügung. Je nach Template sind unterschiedliche Packete im Projekt von beginn an enthalten. Es gibt Templates explizit für Multiplayer. Da die vorhandenen Templates von der verwendeten Unity Version abhängen, wird keins dieser Templates verwendet. Die Templates 'Universal 2D' und 'Universal 3D' sind bei jeder Unity-Version vorhandet. Alle Packete können später manuell hinzugefügt werden. Für diese Anleitung wird das Template 'Universal 2D' verwendet. Bei den Konfigurations-Einstellungen (Unity Organization, Project Name, Locaation) spielt es keine Rolle was eingetragen wird. Mit dem Knopf 'Create Project' wir das Projekt erstellt.



1.2 Hinzufügen des Packets 'NetCode for Gameobjects'

Gehe zu Windows > PackageManagement > Package Manager und klicke auf Package Manager.
Im Package Manager wird Unity Registery ausgewählt.
In der Suchleiste wird nach Nectcode for Gameobjects gesucht.
Klicke auf dieses Package und anschließend auf den Knopf Install.
Wenn die Installation abgeschlossen ist, kann der Package Manager geschlossen werden.
Im Projekt Abschnitt kann überprüft werden ob das Packet Netcode for Gameobjects installiert worden ist.



2. Vorbereitung der Scene

2.1 Hinzufügen des NetworkManagers

In der Szene wird ein leeres GameObject hinzugefügt. Rechtsklick im Bereich der 'Hierarchy' und auf 'Create Empty' klicken.
Das erstellte GameObject wird 'Network Manager' genannt. Rechtklick auf des Gameobject in der Hierarchy, dann 'Rename' klicken und 'Network Manager' eingeben.
Dem GameObject wird eine NetworkManager-Komponente hinzugefügt. Das GameObject 'Network Manager' muss ausgewählt sein, das erkennt man an der blauen Markierung.
Man sieht im Inspector rechts welche Komponenten das Gameobject beinhaltet. Mit dem Knopf 'Add Component' kann eine 'Network Manager'-Komponente dem ausgewählten GameObject hinzugefügt werden.
Wenn die 'Network Manager'-Komponente dem Gamobject hinzugefügt worden ist, sieht man diese im Inspector.



2.2 Hinzufügen der 'Unity Transport'-Komponente

Die NetworkManager-Komponente des NetworkManager-GameObjects ist ein Script. Dieses Skript beinhaltet Variablen.
Die Variable Network-Transport wird auf UnityTransport gestellt.
In der 'Unity Transport'-Komponente werden die vorkonfigurierten Werte vorerst nicht geändert.



2.3 Estellen des PlayerPrefabs

In der Szene wird ein leeres GameObject hinzugefügt. In der Hierarchy rechtslicken und 'Create Empty' auswählen. Dieses wird PlayerPrefab genannt.
Dem GameObject wird eine 'Network Object'-Komponente hinzugefügt.
Dem GameObject wird zudem eine 'Network Transform'-Komponente hinzugefügt.
Im GameObject namens PlayerPrefab gibt es nun eine 'Transform'-Komponente, eine 'Network Object'-Komponente und eine 'Network Transform'-Komponente.


Dem GameObject wird eine 'SpriteRenderer'-Komponente hinzugefügt.



2.4 Estellen des Skripts-Ordners

Im Abschnitt Projekt wird in Assets ein neuer Ordner angelegt.
In Assets Rechtsklicken>Create>Folder. Der Ordner wird Scripts genannt.



2.5 Erstellen des PlayerActionScripts

Der Ordner Scripts wird mit Doppel-Klick geöffnet.
Rechtsklick in den leeren Ordner. Ein Script wird hinzugefügt, Create>Folder>MonoBehaviour-Script. Dieses Script wird PlayerAction genannt.
Das erstellte Script wird mit doppelklicken geöffnet.
Wichtig: Der Name des Skripts muss in der Programmierumgebung der selbe sein wie im Scripts-Ordner.



2.6 Schreiben des PlayerActionScripts

Des PlayerAction-Script kann von hier in die Programierumgebung kopiert werden.
Der Aufbau des Skripts PlayerActions ist Folgender:

using UnityEngine;
using Unity.Netcode;

public class PlayerAction : NetworkBehaviour
{
    public override void OnNetworkSpawn(){
        if (OwnerClientId == 0){
            GetComponent<SpriteRenderer>().color = Color.red;}
        else{
            GetComponent<SpriteRenderer>().color = Color.blue;}
    }

    void Update(){
        if (!IsOwner){
            return;}

        if (Input.GetKeyDown(KeyCode.Space)){
            if (IsHost){
                MoveAndGrow();}
            else if (IsClient){
                MoveAndGrowServerRpc();}
        }
    }

    [ServerRpc]
    void MoveAndGrowServerRpc(){
        MoveAndGrow();}

    void MoveAndGrow(){
        transform.position = new Vector2(Random.Range(-5f, 5f),Random.Range(-5f, 5f));
        transform.localScale += Vector3.one * 0.1f;}
}
Erklärung des Skripts: 1. Das Skript soll nicht von MonoBehaviour erben, sondern von NetworkBehaviour:
public class PlayerAction : MonoBehaviour --> public class PlayerAction : NetworkBehaviour

2. Die Funktion OnNetworkSpawn() wird auf allen Geräten die mit dem Netzwerk verbunden sind für das jeweilige NetworkObject ausgeführt.
Jede Instanz des Spiels auf egal welchem Gerät hat die Variable OwnerClientId.
Der Host hat OwnerClientId=0 ; Der 1. Client hat OwnerClientId=1 ; Der 2. Client hat OwnerClientId=2 ; ...
In jeder Instanz des Spieles wird das Host-PlayerPrefab also als Roter-Kries angezeigt und die Client-PlayerPrefabs als blaue Kriese.
3. Die Funktion 'MoveAndGrow' verändert die Position des GameObjects und vergrößert es.
4. Update() wird in jeder Instanz ausgeführt. Damit der Host oder ein Client nur das eingene PlayerPrefab-GameObject kontrolliert wird abgefragt ob es der Owner ist.
Wenn die Instanz nicht der Owner ist, wird die Update funktion verlassen.
Ist die Instanz der Owner des GameObjects und wird in dieser Instanz die Leertaste gedrückt, soll die Funktion MoveAndGrow ausgeführt werden.
Die Instanz des Hosts ist der wahre Game-State. Dieser Wahre Gamestate der Hostinstanz wird auf allen Clients synchronisiert.
Der Host darf also MoveAndGrow ausführen und so die Position seines PlayerPrefabs direkt ändern und dieser geänderte Game-State der Host-Instanz wird auf allen Clients synchronisiert.

5. Die Instanz des Clients könnte auch direkt MoveAndGrow() ausführen und die Position ihres Playerprefabs in der Client-Instanz ändern.
Die Host-Instanz würde diese Änderung jedoch sofort mit dem Wahren Gamestate der Host-Instanz überschreiben.
Damit eine Änderung wirklich in den Wahren Game-State übergeht muss diese auf der Host-Instanz durchgeführt werden.
Hierzu wird eine ServerRPC (Remote Procedure Call) verwendet. Die Client-Instanz fragt mit MoveAndGrowServerRpc() beim Host/Server nach:
Kannst du für mein PlayerPrefab bitte den Inhalt dieser RPC ausführen? Auf der Host-Instanz wird dann der Inhalt der RPC für das entsprechnede Player-Prefab ausgeführt.

Das Skript PlayerAction wird nun dem GameObject PlayerPrefab hinzugefügt.
Dazu wird das Gameobject PlayerPrefab geöffnet, AddComponent>PlayerAction.



2.7 Erstellen des Prafab-Ordners

Im Projekt Abschnitt wird in Assets ein Ordner namens Prefabs erstellt, Rechtsklick>Create>Folder.
Der Ordner wird Prefabs genannt.
Das GameObject PlayerPrefab wird aus der Scene in den Prefabs-Ordner gezogen.

Das PlayerPrefab GameObject wird aus der Szene gelöscht.

2.8 Aktivieren des alten Input-Systems

Die Funktion Input.GetKeyDown(KeyCode.Space) funktioniert im neuen, standardmäßig aktivem Input-System nicht. Das alte InputSystem wird deshalb aktiviert.
Dafür werden die Project-Settings geöffnet, Edit>Projekt Settings.
In den Projekt Settings wird der Abschnitt Player ausgewählt.
In der Suchleiste wird Active Input Handling aingegeben.
Active Input Handling muss auf BOTH gestellt sein. Nach dem Umstellen fordert Unity einen Restart. Dieser kann bestätigt werden.

2.11 Erstellen des MainCanvas

Um als Host zu arbeiten oder sich als Client zu verbinden muss im Inspector auf 'Start Host' oder Start Client geklickt werden.
Wenn das Spiel später als Anwendung existiert und nicht im Unity Editor ausgeführt wird, gibt es keinen Inspector und keinen 'Start Host' oder Start Client Knopf.
Die Auswahl der Rolle im Netzwerk (Host oder Client) muss auf eine andere Weise durchgeführt werden.
Dazu wird der Scene ein Canvas hinzugefügt. Rechtsklick UI>Canvas. Wir nennen das GameObject MainCanvas.
Unter dem Canvas UserInterface fügen wir zwei Buttons ein. Rechtsklick, UI>Button-Text Mesh Pro.
Man wird dazu aufgefordert die TMP Essentials zu importieren. Dies wird getan.
Das GameObject des erste Buttons wird StartHostButton genannt.
Das GameObject des zweite Button wird StartClientButton genannt.



In den GameObjects der Buttons gibt es ein GameObject, dass Text (TMP) heißt. Öffnet dieses Text (TMP)-GameObject sodas die Komponenten im Inspector angezeigt werden.
Die Anzeigebeschriftung der Buttons lässt sich über das Textfeld im Inspektor festlegen.
Die Anzeigebeschriftung der Buttons wird jeweils zu Start Host und zu Start Client festgelegt.
Anschließend werden die Buttons, wie im Bild unten gezeigt, angeordnet.



Im GameObject MainCanvas wird mit 'UI > Input Field - TextMeshPro' ein Input Field erstellt.
Dieses InputField-GameObject wird 'IP_Address_InputField' genannt.
In der Szene wird das 'IP_Address_InputField' über dem 'Start Host'-Knopf positioniert.
Im InputField-GameObject befindet sich ein GameObject mit der Bezeichung Placeholder. Das Placeholder GameObject wird ausgewählt.
Im Inspector findet man ein Textfeld. In dieses Text-Feld wird 'Enter IP-Adress' eingegeben.



Im GameObject MainCanvas wird mit 'UI > Input Field - TextMeshPro' ein weiters Input Field erstellt.
Dieses InputField-GameObject wird 'Port_InputField' genannt.
In der Szene wird das 'IP_Address_InputField' über dem 'Start Host'-Knopf und unter dem 'IP_Address_InputField' positioniert.
Im InputField-GameObject befindet sich ein GameObject mit der Bezeichung Placeholder. Das Placeholder GameObject wird ausgewählt.
Im Inspector findet man ein Textfeld. In dieses Text-Feld wird 'Enter Port' eingegeben.



2.12 Erstellen des NetworkRoleSelect-Skripts

Die Knopfe sind erstellt, jedoch haben sie keine Funktion. Die Betätigung der Knöpfe bewirkt nichts.
Im Script Ordner wird ein neues Skript erstellt. Rechtsklick, Create>Scripting>MonoBehaviour Script. Dieses Script wird ChooseNetworkRole genannt

Das NetworkRoleSelect-Skripts beinhaltet folgendes Programm.

using Unity.Netcode;
using UnityEngine;
//Add
using Unity.Netcode.Transports.UTP;

public class ChooseNetworkRole : MonoBehaviour
{
    public NetworkManager networkManager;

    //Add this Variable
    public TMPro.TMP_InputField ipAddress_Field;
    public TMPro.TMP_InputField port_Field;

    void Start()
    {
        networkManager = GetComponent<NetworkManager>();
        if(networkManager == null)
        {
            Debug.Log("No reference to NetworkManager");
        }

        ipAddress_Field = GameObject.Find("IP_Address_InputField").GetComponent<TMPro.TMP_InputField>();
        port_Field = GameObject.Find("Port_InputField").GetComponent<TMPro.TMP_InputField>();
    }

    public void RunAsHost()
    {
        Debug.Log("Tried to start Host");
        ushort.TryParse(port_Field.text, out ushort port);
        networkManager.GetComponent<UnityTransport>().SetConnectionData(ipAddress_Field.text, port);
        networkManager.StartHost();
        DeactivateUserInterface();
    }

    public void RunAsClient()
    {
        Debug.Log("Tried to start Client");
        ushort.TryParse(port_Field.text, out ushort port);
        networkManager.GetComponent<UnityTransport>().SetConnectionData(ipAddress_Field.text, port);
        networkManager.StartClient();
        DeactivateUserInterface();
    }

    private void DeactivateUserInterface()
    {
        GameObject.Find("MainCanvas").SetActive(false);
    }
}
Erklärung des Skripts: 1. :

Das ChooseNetworkRole-Skript wird dem 'Network Manager'-Gameonject als Komponente hinzugefügt.
Das 'Start Host Button'-Gameobject besitzt die Komponente Button. Dieser Komponente wird eine OnClick()-Funktion hinzugefügt.


Der OnClick()-Funktion des wird das NetworkManager-GameObjectls Komponente zugeordnet.
Beim 'Start Host Button' wird die Funktion auf ChooseNotworkRole>RunAsHost() gestellt.
Beim 'Start Client Button' wird die Funktion auf ChooseNotworkRole>RunAsClient() gestellt.

3. Builden des Spiels

Im 'Network Manager'-GameObject wird in der 'Unity Transport'-Komponente der Hacken bei 'Enalbe Remote Connection' aktiviert.
Das 'Build Profiles'-Fenster wird geöffnet. File > Build Profiles.
Im 'Build Profiles'-Fenster wird auf Build geklickt.


Es öffnet sich der Projekt-Ordner und es muss ein Ordner ausgewählt werden, in dem die Build-Datein gespeichert werden.
Es wird dashalb ein neuer Ordner erstellt und dieser wird 'Builds' genannt.
Der erstellte Builds-Ornder wird ausgewählt und mit dem 'Ordner auswählen'-Knopf wird der Build-Prozess gestartet. Der Build-Prozess kann einige Minuten dauern.
Ist der Build-Prozess abgeschlossen, befindt sich die Anwendung im Builds-Ornder.


4. Vervielfältigen und spielen des Spiels


Der Build-Ordner kann auf jeden Computer mit dem Betriebssystem Windows kopiert werden. Die Anwendung kann dann diesem ausgeführt werden.

4.1 Mehrere Anwendungen auf einem Gerät


Auf einem Gerät können mehere Instanzen der selben Anwendungen gestartet werden.
Dies eignet sich vorallem zum überprüfen ob die Anwengung funktioniert.


4.2 Mehrere Anwendungen im lokalen Netzwerk


Es können auch mehrere Instanzen auf mehreren unterschiedlichen Geräten im selben Netzwerk ausgeführt werden.
Beispielsweise auf einem Laptop und einem Desktop-Computer


4.3 Mehrere Anwendungen in verschiedenen lokalen Netzwerken


Es können auch mehrere Instanzen auf mehreren unterschiedlichen Geräten in unterschiedlichen Netzwerken ausgeführt werden.
Die Person aus dem 1. Netzwerk sieht die Geräte im 2. Netzwerk nicht. Sie kann nur mit dem Router kommunizieren.
Damit die Komunikation hier funktionieren kann muss der Router und die Firewall entsprechend konfiguriert werden.
